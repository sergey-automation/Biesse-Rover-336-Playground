# Техническое задание: контроллер исследования SIR88 на RP2040

Редакция 1.1 — 28.11.2026. Проектирование; реализация кода в данное ТЗ не входит.

## 1. Назначение и терминология

Контроллер выполняет пакеты экспериментальных Command-команд на отдельном стендовом модуле SIR88, принимает и сохраняет RS-ответы, передаёт результаты компьютеру по USB. Подключение исполнительных нагрузок станка не входит в стендовые испытания.

- Frame-кадр — единица передачи по линии.
- Command-команда — один Frame-кадр ведущего.
- RS-ответ — один Frame-кадр ведомого.
- Слово — 9 информационных бит UART, хранится в uint16_t. Полное слово на линии: старт, 9 бит данных, стоп (11 бит).
- ACK, RET, NAK — отдельные однословные служебные Frame-кадры ведущего. Их применение к SIR88 является экспериментальной гипотезой, а не подтверждённой спецификацией производителя.

## 2. Аппаратная платформа

- RP2040, RAM 264 КиБ (270336 байт), системная частота 120 МГц.
- Одно процессорное ядро и PIO (программируемые аппаратные автоматы ввода-вывода); второе ядро не используется.
- RS-485, ST3485EBDR, питание трансивера 3,3 В.
- GP0 — DI, GP1 — DE, GP2 — /RE, GP3 — RO.
- USB — связь с компьютером; USB CDC-ACM (виртуальный COM-порт).
- Flash: хранение и чтение программы и неизменяемых таблиц. Запись и стирание Flash во время исполнения запрещены.
- Все изменяемые настройки, команды и результаты находятся в RAM.

## 3. Параметры линии

UART 750000 бод, 9N1, без искусственных пауз между передаваемыми словами Frame-кадра. Слова передаются младшим битом вперёд.

База: 1 бит = 160 тактов = 1,333333 мкс; 1 слово = 1760 тактов = 14,666667 мкс.

| Параметр | Длительность в словах | мкс | Такты |
|---|---:|---:|---:|
| Ожидание начала RS после Command | 5 | 73,333333 | 8800 |
| Межсловный тайм-аут RX | 0,9 | 13,2 | 1584 |
| Минимальный период Command | 22 | 322,666667 | 38720 |
| Период Command по умолчанию | 24 | 352 | 42240 |
| Ожидание начала RS после RET | 5 | 73,333333 | 8800 |
| Дополнительная задержка перед ACK/RET/NAK | 0 | 0 | 0 |

Период Command отсчитывается между началами исходных Command-команд. Следующая Command не начинается до завершения текущего обмена и истечения установленного периода. Тайм-аут начала RS отсчитывается от окончания последнего стопового бита переданного Frame-кадра; межсловный — от окончания стопового бита принятого слова до начала следующего стартового бита. Начало следующего слова до истечения тайм-аута отменяет ожидание окончания Frame-кадра.

Задержка перед служебным подтверждением — дополнительная к межсловному тайм-ауту и фактическим аппаратным задержкам. В Python пользователь задаёт времена в мкс; контроллер использует такты, Python пересчитывает результаты обратно в мкс. Округление до ближайшего такта (при половине такта — вверх). Допустимые значения ожидания начала RS и после RET: 1–65535 тактов; межсловный тайм-аут: 1–65535 тактов; дополнительная задержка: 0–65535 тактов; период Command: 38720–4294967295 тактов. Недопустимые значения отклонять, не округлять до границы диапазона.

Справочно: оригинальный MDB 1993, раздел 3.1, задаёт максимальную реакцию 5 мс и межсловную паузу 1 мс при 9600 бод. Это соответственно 4,364 и 0,873 длительности слова; минимальная задержка реакции не задана. Параметры настоящего ТЗ — собственные стендовые настройки, не норматив MDB или SIR88.

## 4. Управление трансивером

| Состояние | DE | /RE |
|---|---:|---:|
| Передача | 1 | 1 |
| Приём и ожидание | 0 | 0 |
| Тест собственного TX (не рабочий режим) | 1 | 0 |

Независимое управление DE и /RE. В рабочем режиме собственный TX не принимается. Перед началом передачи обеспечить готовность трансивера, после последнего стопового бита освободить шину и включить приём. Точные аппаратные задержки необходимо проверить при реализации; не допускать обрезания стопового бита. Между Command передатчик отключён. Вне предусмотренного окна RX результаты не записываются.

## 5. Пакет заданий

От 1 до 512 Command-команд. Порядковый номер в записи не передаётся: порядок задаётся положением в пакете. Настройки общие для пакета, если не указано иначе.

| Индивидуальное поле Command | Тип | Байт | Диапазон |
|---|---|---:|---|
| TX_LEN | uint8 | 1 | 1–7 |
| RX_EXPECTED_MIN | uint8 | 1 | 1–6 |
| RX_EXPECTED_XOR | uint16 | 2 | 0x000–0x1FF; типовое значение 0x100 |
| TX_WORDS[7] | uint16[7] | 14 | каждое 0x000–0x1FF |
| **Итого** | | **18** | |

Передаются только заданные слова Command; не дополнять Frame-кадр до семи слов на линии. Контроллер не изменяет исходные слова и не формирует автоматически контрольную сумму TX.

Общие параметры: число Command, времена из раздела 3, AUTO (0/1, по умолчанию 0), максимальное число RET (0–5, по умолчанию 0). RET=0 означает отсутствие повторных запросов RS через 0x0AA; при AUTO=1 неполный RS в этом случае завершает обмен с NAK. Формат USB-сериализации определён в разделе 9.

## 6. Приём и запись результатов

- Принимаются последовательные слова до межсловного тайм-аута. Ожидаемая длина не является условием немедленного прекращения RX.
- Сохраняются только первые шесть слов каждого RS. XOR вычисляется только по сохранённым словам, по всем девяти битам, включая последнее сохранённое слово. После шестого слова дополнительные значения не сохраняются и в XOR не участвуют.
- Счётчик принятых слов ограничен 255. При достижении 255 приём завершается и осуществляется переход к следующей Command без дальнейших подтверждений; это ограничитель непрерывного потока, а не отдельная система диагностики длинных ответов.
- Шесть слов уже являются поводом для ручного исследования другими инструментами; дополнительных проверок переполнения не вводить.
- Маска ошибок: бит 0 соответствует первому сохранённому слову, бит 5 — шестому. Установленный бит означает ошибку приёма этого слова. Отдельные общие флаги UART не дублировать. Минимально фиксировать ошибку стопового бита; возможности выявления других физических ошибок требуют проверки реализации PIO.
- Задержка начала RS сохраняется в тактах. Межсловные интервалы не сохраняются.
- Каждый первоначальный RS и каждый RS после RET сохраняется отдельно, в том числе пустая попытка. Повторная попытка не перезаписывает предыдущую.

## 7. Обработка обмена

Критерии правильности RS пока экспериментальные: минимальная ожидаемая длина, отсутствие ошибок сохранённых слов, совпадение XOR с индивидуальным RX_EXPECTED_XOR. AUTO=0 выполняет те же измерения и проверки, но не передаёт подтверждений и не инициирует RET.

AUTO=1: проектные значения служебных слов — ACK 0x000, RET 0x0AA, NAK 0x0FF. После ACK и NAK текущий обмен завершён; дополнительных RS-слотов не создаётся. После RET открывается новое окно RX. RET не означает повтор исходной Command.

| Ситуация | Согласованная реакция |
|---|---|
| Первоначальный RS отсутствует | Не передавать подтверждение; дождаться периода Command и перейти к следующей |
| RS достаточно длинный, без ошибок, XOR совпадает | ACK |
| RS неполный, без ошибок, даже при совпадении XOR | RET в пределах лимита |
| Одиночный 0x0AA | RET в пределах лимита |
| После RET отсутствует RS | Повтор RET в пределах лимита |
| Ошибка приёма сохранённых слов | NAK (ранее согласованное правило) |
| Достаточная длина, XOR не совпадает | NAK (ранее согласованное правило) |
| Неуспешная попытка после исчерпания RET | NAK, завершить обмен |
| Получено 255 непрерывных слов | Завершить приём и перейти к следующей Command |

Приоритет правил: 255 слов — завершение без подтверждения; отсутствие первоначального RS — завершение без подтверждения; ошибка стопового бита любого из первых шести слов — NAK; отсутствие RS после RET, одиночный 0x0AA без ошибки или недостаточная длина — RET при наличии лимита, иначе NAK; достаточная длина и совпадение XOR — ACK, иначе NAK. При AUTO=0 подтверждения не передаются ни при каких условиях. Счётчик RET увеличивается только после фактической передачи 0x0AA. При 255 словах очередная Command всё равно соблюдает минимальный период. Не сохранять слова после шестого и не учитывать их ошибки или XOR.

## 8. RAM и формат результатов

На каждую Command резервируется шесть слотов RS: первоначальный и пять возможных повторных.

| Поле одного слота RS | Тип | Байт |
|---|---|---:|
| RX_WORDS[6] | uint16[6] | 12 |
| RX_COUNT (0–255) | uint8 | 1 |
| RX_ERROR_MASK | uint8 | 1 |
| CONFIRM_TYPE | uint8 | 1 |
| VALID (признак выполненной попытки) | uint8 | 1 |
| RX_XOR | uint16 | 2 |
| RX_START_DELAY_TICKS | uint16 | 2 |
| **Итого** | | **20** |

CONFIRM_TYPE: 0 — ничего не передано, 1 — ACK, 2 — RET, 3 — NAK. VALID: 0 — слот не использован, 1 — попытка выполнена, в том числе пустая. Для пустого RS RX_START_DELAY_TICKS=0, RX_XOR=0, маска ошибок=0; Python определяет отсутствие RS по RX_COUNT=0 при VALID=1. Незанятые слова и слоты обнуляются. Число RET восстанавливается по сохранённым типам подтверждения, отдельный буфер не нужен.

uint16 задержки допускает 0–65535 тактов (до 546,125 мкс); при текущих окнах 8800 тактов этого достаточно. Окна ожидания ограничены 65535 тактами (см. раздел 3). Не допускать молчаливого переполнения.

Расчёт статического основного буфера:

- Command: 18 байт; 6 RS × 20 = 120 байт.
- На одну Command: 138 байт.
- На 512 Command: 70656 байт = 69 КиБ (26,14% RAM).
- Остаток: 199680 байт = 195 КиБ до вычета стеков, USB, PIO-обслуживания и прочих переменных.

Раскладка структуры должна быть проверена при компиляции. Служебные поля пакета и временные переменные в расчёт не включены. При статическом выделении память не зависит от фактического размера пакета.

## 9. Обмен с компьютером и жизненный цикл

### 9.1. Транспорт и формат сообщений

USB CDC-ACM, Python pyserial. Это поток байтов: границы USB-транзакций не являются границами сообщений. Все многобайтовые поля прикладного USB-протокола передаются little-endian (младший байт первым). Формат не зависит от выравнивания структур C. Не передавать текстовые логи в этом же потоке.

| Поле | Тип / размер | Значение |
|---|---|---|
| MAGIC | 2 байта | A5 5A (именно в этом порядке) |
| OPCODE | uint8 | Код сообщения |
| PAYLOAD_LEN | uint32 | Число байтов полезных данных |
| PAYLOAD | PAYLOAD_LEN байт | По таблице операций |
| CRC32 | uint32 | CRC-32/ISO-HDLC над OPCODE, PAYLOAD_LEN (4 байта на линии) и PAYLOAD; MAGIC не включать |

CRC32: полином 0x04C11DB7 (отражённый 0xEDB88320), init=0xFFFFFFFF, refin/refout=true, xorout=0xFFFFFFFF; контрольный пример ASCII `123456789` → 0xCBF43926. Совместимо с Python `zlib.crc32`. Максимальная длина PAYLOAD — 70660 байт (результат полного пакета). Приём частями допустим. При неверной длине или CRC не выполнять операцию; восстановить синхронизацию по MAGIC. Не выделять второй буфер размером с весь пакет результатов: сериализовать выгрузку непосредственно из основного буфера, вычисляя CRC постепенно.

### 9.2. Коды операций

| OPCODE | Направление | PAYLOAD | Результат |
|---|---|---|---|
| 01 | ПК → RP2040 | Настройки + Command-записи (см. 9.3) | 81 либо FF |
| 02 | ПК → RP2040 | Пустой | Запуск загруженного пакета: 81, затем 82 |
| 03 | ПК → RP2040 | Пустой | Повтор нормального завершённого пакета: 81, затем 82 |
| 04 | ПК → RP2040 | Пустой | Отмена дальнейшего исполнения: 81 |
| 05 | ПК → RP2040 | Пустой | 85 — текущие настройки |
| 06 | ПК → RP2040 | Пустой | 86 — состояние |
| 81 | RP2040 → ПК | uint8 исходного OPCODE | Успешно принято |
| 82 | RP2040 → ПК | Результаты (см. 9.4) | Автоматическая выгрузка |
| 85 | RP2040 → ПК | Блок настроек (см. 9.3) | Ответ на 05 |
| 86 | RP2040 → ПК | uint8 состояния | Ответ на 06 |
| FF | RP2040 → ПК | uint8 исходного OPCODE, uint8 ошибки | Операция отклонена |

Коды ошибки: 1 — неизвестная операция; 2 — неверная длина; 3 — неверный CRC; 4 — недопустимое значение поля; 5 — операция недопустима в текущем состоянии; 6 — внутренняя ошибка. При невозможности определить исходный OPCODE использовать 0. ПК не передаёт следующую операцию до получения ответа, кроме STOP, который может быть поставлен в очередь до окончания пакета. Перед исполнением передать 81; после исполнения передать 82. Отдельного запроса выгрузки не требуется.

### 9.3. Блок настроек и загрузка пакета

Поля передаются в указанном порядке, без padding (байтов выравнивания):

| Поле | Тип | Значение по умолчанию |
|---|---|---:|
| COMMAND_COUNT | uint16 | 0 после включения; при LOAD 1–512 |
| AUTO | uint8 | 0 |
| RET_MAX | uint8 | 0 |
| RX_START_TIMEOUT | uint32 | 8800 |
| RX_GAP_TIMEOUT | uint32 | 1584 |
| COMMAND_PERIOD | uint32 | 42240 |
| RET_RX_TIMEOUT | uint32 | 8800 |
| CONFIRM_DELAY | uint32 | 0 |

Блок настроек — 24 байта. В LOAD за ним следуют COMMAND_COUNT записей по 18 байт в порядке полей раздела 5. Неиспользованные TX_WORDS должны быть нулевыми. Длина PAYLOAD LOAD = 24 + 18 × COMMAND_COUNT (максимум 9240 байт). Проверять весь пакет, диапазоны и CRC до разрешения исполнения. После начала приёма нового LOAD старый пакет больше не разрешён к исполнению; при неудачной загрузке перейти в состояние без готового пакета. После успешной загрузки очистить аппаратный RX FIFO PIO, буфер предыдущих RS, счётчики и флаги. LOAD не запускает опрос самостоятельно: требуется 02. Настройки после перезапуска — значения по умолчанию; сохранённых Command нет.

### 9.4. Выгрузка результатов

PAYLOAD 82: uint8 статус завершения (0 — нормальное, 1 — внутренняя авария), uint8 резерв=0, uint16 количество выполненных Command. Далее для каждой выполненной Command в исходном порядке: запись Command (18 байт) и шесть записей RS (по 20 байт, поля в порядке раздела 8). Длина = 4 + 138 × количество выполненных Command. Невыполненные Command не выгружать. Пустая попытка отличается от неиспользованного слота по VALID. При нормальном завершении количество выполненных Command равно COMMAND_COUNT. Отсутствие RS, NAK, исчерпание RET и предел 255 слов являются результатами измерения, а не авариями контроллера. Авария — внутренняя ошибка, из-за которой пакет нельзя продолжить (например, невозможность дальнейшего обслуживания PIO); по возможности освободить шину, выгрузить завершённые измерения и запретить повтор. При аппаратном зависании выгрузка не гарантируется.

### 9.5. Состояния и последовательность работы

Состояния для 86: 0 — нет пакета; 1 — загружен, готов к первому запуску; 2 — выполняется; 3 — нормально завершён, разрешён повтор; 4 — авария, нужен новый LOAD; 5 — остановлен, нужен новый LOAD. Состояние 2 не требует обслуживания запросов USB внутри пакета.

1. Загрузить полный пакет через 01, проверить его, очистить предыдущие результаты, ответить 81.
2. По 02 начать исполнение. До первого TX очистить RX FIFO; перед каждым новым окном RX исключить попадание остаточных данных предыдущего окна (очистка/переинициализация до момента разрешения приёма, не после начала возможного RS).
3. Выполнить все Command и RET автономно, на одном ядре с PIO. Не выполнять прикладные USB-команды внутри пакета и не передавать результаты промежуточно.
4. После пакета выгрузить 82 и только затем обработать поступившие USB-команды. USB-служебное обслуживание для сохранения соединения допустимо при условии, что оно не нарушает временные характеристики RS-485.
5. По 03 (только из состояния 3) очистить FIFO, результаты, счётчики и флаги, сохранив исходные Command и настройки; повторить один пакет. По 04 перейти в состояние 5, освободить линию, не запускать следующий пакет. По новому 01 принять новые задания. Автоматического бесконечного повторения нет.

STOP действует исключительно между пакетами, после выгрузки данных; не прерывает Command или текущий пакет. Если пользователь хочет остановить серию, Python не посылает следующий запуск. При фактическом зависании программный STOP не гарантирует восстановления; аппаратный сброс/перезапуск остаётся внешним способом восстановления. После аварии или STOP повтор без нового LOAD запрещён.

## 10. Не входит в текущую реализацию

Bus Reset, пассивное прослушивание линии, второе ядро, запись во Flash, собственный RX при обычном TX, сохранение межсловных интервалов, дополнительные проверки длинных RS, управление реальными исполнительными нагрузками станка.

## 11. Критерии проверки реализации

На изолированном стенде или симуляторе ведомого проверить: формат 9N1 и длительность слова; отсутствие TX-пауз и обрезания стопового бита; времена RX и периоды Command; сохранение всех попыток; обработку пустых, неполных и ошибочных RS; ограничение 255 слов; AUTO=0 без подтверждений; загрузку и выгрузку пакета из 512 записей; повтор после нормального завершения; отсутствие записи Flash. Проверить фактическое потребление RAM по map-файлу.

## 12. Решения редакции 1.1 и границы реализации

- RET_MAX=0 по умолчанию — последнее прямое указание пользователя. AUTO=0 по умолчанию принят для диагностического режима без служебных передач; оба параметра задаются на весь пакет.
- Формат USB CDC-ACM, MAGIC, CRC32, коды сообщений, поля настроек и результата, состояния, диапазоны времени и правила очистки определены в настоящей редакции как проектные решения, а не требования стандарта MDB. Они являются обязательным контрактом между прошивкой и Python для реализации этой редакции.
- Ошибка стопового бита имеет приоритет над распознаванием одиночного 0x0AA. Дополнительные физические ошибки не вводить без возможности их достоверного измерения.
- Аппаратные задержки ST3485EBDR, фактическая точность измерения начала RS, работа USB на границе пакетов и отсутствие записи Flash должны быть проверены при реализации на стенде. Это критерии проверки, а не разрешение менять согласованные параметры.
- Не реализовывать дополнительные режимы или проверки длинных RS сверх описанных. Не считать гипотезы о семантике конкретных Command-команд SIR88 установленными.
